# FRONT-001 — Привести компоненты лендинга Nordel в соответствие с макетами

- **Исполнитель:** Frontend.
- **Статус:** реализация выполнена; остаются визуальная приёмка, кросс-браузерная проверка и внешние зависимости.
- **Цель:** воспроизвести все секции и элементы концептов в коде, обеспечить соответствие светлой и тёмной тем и точно описать реализованные компоненты.

Изображения содержат последовательные секции лендинга. Необходимо восстановить их порядок и композицию, учитывая возможные пересечения между снимками.

Документация проекта:

- [Декомпозиция компонентов](../landing-components.md).
- [Разработка и проверка лендинга](../landing-development.md).

Отсутствие подключения файлов `screen_*.png` в коде само по себе не доказывает несоответствие. Это эталонные макеты: интерфейс необходимо воспроизвести компонентами, а не заменить страницу одним изображением. Точный перечень расхождений составляется после визуального изучения всех шести файлов.

## Объём работ

### 1. Инвентаризация и сопоставление

- Визуально изучить все шесть изображений.
- Составить полный перечень секций и вложенных элементов, включая текст, кнопки, иконки, иллюстрации и декоративные элементы.
- Для каждого элемента указать исходное изображение и область, компонент, файл реализации, различия светлой и тёмной темы и статус соответствия.
- Проверить каждый пункт C01–C18 в `docs/frontend/landing-components.md` по изображениям. Существующее описание не считать доказательством наличия компонента в макете.
- Дополнить пропуски, исправить неточности, отдельно обозначить технические компоненты. Не добавлять пользовательские секции только на основании предположений в документации.

Таблица сопоставления должна содержать как минимум:

| Изображение и область | Секция / элемент | Компонент и файл реализации | Отличия Light/Dark | Статус / расхождения |
|---|---|---|---|---|
| Заполнить после просмотра макетов | — | — | — | — |

### 2. Реализация компонентов

- Доработать разметку, стили и поведение всех компонентов по результатам сопоставления.
- Воспроизвести порядок блоков, сетки, размеры, отступы, типографику, цвета, границы, тени, иконки, иллюстрации и декоративные элементы.
- Перенести читаемые тексты точно. Неразборчивые фрагменты отметить для уточнения.
- Использовать переиспользуемые компоненты для повторяющихся элементов.
- Обеспечить работоспособность интерактивных элементов; поведение, которое нельзя определить по статическому изображению, сверять с требованиями проекта и описывать отдельно.

### 3. Архитектура и документация

- Сохранить текущий стек: Webpack, Handlebars, SCSS, vanilla JS.
- Использовать текущие каталоги `pages/`, `src/templates/partials/`, `src/styles/`, `src/modules/`, `src/data/`.
- Хранить контент в данных страниц, разметку в шаблонах, интерактивность в JS-модулях.
- Подключить новые компоненты и ресурсы к существующей сборке.
- Привести документацию к фактической структуре проекта, устранив противоречие с предложенной структурой `site/`.
- Обновить `docs/frontend/landing-components.md`, включив полный перечень компонентов и таблицу соответствия макетам.
- При изменении порядка разработки, подключения ресурсов или проверки обновить `docs/frontend/landing-development.md`.

### 4. Светлая и тёмная темы

- Использовать общую структуру компонентов и тематические токены без дублирования разметки по темам.
- Воспроизвести различия обеих тем по соответствующим изображениям.
- Проверить переключение и сохранение темы, системное предпочтение при отсутствии сохранённого выбора.
- Проверить состояния интерактивных элементов и читаемость контента в обеих темах.

### 5. Адаптивность и доступность

- Обеспечить корректную композицию на desktop, tablet и mobile.
- Если мобильных макетов нет, описать принятые решения по перестроению секций и навигации.
- Обеспечить доступную мобильную навигацию, управление с клавиатуры и видимый фокус.
- Использовать семантические кнопки и ссылки, корректные `alt` для изображений и обозначение декоративных элементов.
- Проверить контраст и поддержку `prefers-reduced-motion` при наличии анимаций.

### 6. Контент и зависимости

- Сохранить термин «вишлист».
- Адрес Telegram-бота, домен, ссылки и отсутствующий контент не выдумывать.
- Неизвестные значения перечислить как зависимости для завершения соответствующих функций; не выдавать заглушки за рабочую интеграцию.
- Для вишлиста обеспечить переход на согласованный адрес бота. Разработка бота и бэкенда в эту задачу не входит.

## Текущее состояние этапов

- Инвентаризация, таблица компонентов и реализация трёх секций выполнены; расхождения перечислены в [отчёте проверки](001-validation.md).
- Светлая/тёмная темы и адаптивность проверялись в Chrome на 375/768/1440 px; сохранены шесть сценариев и шесть сравнений с эталонами.
- Дополнительно реализован footer на главной и About по запросу пользователя: логотип, меню, кнопка вишлиста, юридические ссылки-заглушки и копирайт.
- Документация синхронизирована с footer. Отдельный сохранённый отчёт о его браузерной проверке отсутствует; подробности и матрица повторной проверки — в отчёте.
- Не закрыты точное визуальное соответствие, полный аудит доступности, Firefox/WebKit, адрес Telegram-бота и домен. Юридические ссылки `#` согласованы как заглушки.

## Критерии приёмки

Отметки ниже опираются на сохранённый отчёт лендинга до отдельной приёмки footer, а не на новый запуск тестов. Сборки и ESLint описаны в отчёте, но отдельные логи к критерию сборок не приложены; полная доступность и визуальное соответствие остаются открытыми.


- [x] Все шесть изображений просмотрены и сопоставлены с реализацией.
- [ ] Каждый видимый элемент макетов отражён в таблице соответствия; нет пропущенных или случайно продублированных секций.
- [ ] На ширине исходных макетов совпадают композиция, текст, размеры и оформление. Оставшиеся расхождения явно перечислены и требуют рассмотрения при приёмке.
- [x] Подготовлены скриншоты реализации и сравнения наложением с каждым из шести эталонов при одинаковом масштабе и соответствующих областях страницы.
- [x] Дополнительно проверены ширины 375, 768 и 1440 px в обеих темах: нет горизонтального скролла, обрезанного текста и недоступных элементов.
- [x] Навигация, CTA и переключатель темы работают; неизвестные адреса и другие зависимости явно отмечены как незавершённые пункты.
- [ ] Интерактивные элементы доступны с клавиатуры, имеют видимый фокус и необходимые доступные названия и состояния.
- [x] Отсутствуют ошибки консоли и загрузки ресурсов.
- [ ] Успешно выполнены `npm run build:dev`, `npm run build:prod`, `npm run lint`; результаты приложены. Отсутствующая конфигурация линтера не считается успешной проверкой.
- [x] Обновлены описания компонентов и необходимые инструкции разработки.
