# Инструкция по запуску и поддержке лендинга

## Назначение

Проект — статический многостраничный лендинг Nordel, собираемый Webpack.

Используемые технологии:

- Webpack 5;
- Handlebars для HTML-шаблонов;
- SCSS для стилей;
- JavaScript-модули без фреймворка;
- PostCSS и Autoprefixer;
- отдельные сборки для dev и prod.

## Требования

Перед началом работы установите:

- Node.js, совместимый с установленными версиями зависимостей (проверяйте поле `engines` в пакетах; Node 18 не является гарантированно поддерживаемой базой);
- npm 9 или новее.

Проверка версий:

```bash
node --version
npm --version
```

## Установка зависимостей

Из корня проекта выполните:

```bash
npm install
```

Команда создаст папку `node_modules` и установит зависимости из `package.json`.

## Запуск режима разработки

Для запуска Webpack Dev Server:

```bash
npm run start
```

После запуска откройте:

```text
http://localhost:3000
```

В режиме разработки доступны:

- пересборка при изменении файлов;
- Hot Module Replacement;
- source map;
- подробные сообщения об ошибках;
- dev-server хранит сборку в памяти; запись в `build/dev` выполняет `npm run build:dev`.

Остановить сервер можно сочетанием `Ctrl+C`.

## Сборка без запуска сервера

Разработка:

```bash
npm run build:dev
```

Результат будет записан в:

```text
build/dev/
```

Production:

```bash
npm run build:prod
```

Результат будет записан в:

```text
build/prod/
```

Команда по умолчанию:

```bash
npm run build
```

Она выполняет production-сборку.

Production-сборка включает:

- минификацию JavaScript;
- минификацию CSS;
- content hash в именах ресурсов;
- очистку предыдущего содержимого каталога сборки;
- отдельные HTML, JS и CSS-файлы для страниц.

## Структура проекта

```text
pages/                         исходные страницы Handlebars
src/
  data/                        данные страниц
  modules/                     JavaScript-модули
  styles/                      SCSS
    base.scss                  общие токены и базовые стили
    pages/                     стили отдельных страниц
  templates/
    layouts/                   общие HTML-layout
    partials/                  переиспользуемые HTML-компоненты
webpack/
  pages.js                     единый список страниц и их зависимостей
  webpack.common.js            общая конфигурация
  webpack.dev.js               dev-конфигурация
  webpack.prod.js              production-конфигурация
build/
  dev/                         результат dev-сборки
  prod/                        результат production-сборки
```

## Добавление новой страницы

1. Создайте шаблон в `pages/`, например `contacts.hbs`.
2. Создайте данные в `src/data/contacts.js`.
3. Добавьте страницу в `webpack/pages.js`.
4. Укажите JavaScript-модули в поле `modules`.
5. Укажите SCSS-файлы в поле `styles`.
6. Запустите `npm run build:dev`.

Пример записи:

```js
contacts: {
  template: './pages/contacts.hbs',
  data: './src/data/contacts.js',
  modules: ['theme-toggle', 'navigation', 'wishlist'],
  styles: ['base', 'pages/contacts']
}
```

Для страницы с отдельными стилями создайте:

```text
src/styles/pages/contacts.scss
```

## Добавление переиспользуемого компонента

HTML-компоненты находятся в:

```text
src/templates/partials/
```

Порядок добавления:

1. Создайте partial, например `feature-card.hbs`.
2. Partials верхнего уровня автоматически регистрируются по имени файла из `src/templates/partials/` при запуске Webpack.
3. Подключите его в нужной странице через:

```hbs
{{> feature-card}}
```

Интерактивность компонента должна находиться в отдельном файле:

```text
src/modules/feature-card.js
```

Стили компонента добавляйте в SCSS-файл компонента или страницы и подключайте его через `styles` в `webpack/pages.js`.

## Изменение контента

Текст и SEO-данные страницы следует хранить в `src/data/`, а не дублировать в конфигурации Webpack.

Основные поля:

```js
module.exports = {
  lang: 'ru',
  title: 'Название страницы',
  description: 'SEO-описание страницы',
  canonical: 'https://example.com/page.html'
};
```

Переиспользуемая разметка хранится в Handlebars partials.

## Темы

Переключатель темы использует атрибут:

```html
<html data-theme="dark">
```

Цвета и основные параметры находятся в `src/styles/base.scss`.

Для новой темы добавляйте значения CSS-переменных в блок `:root[data-theme="..."]`.

## Правила поддержки

- Не дублируйте общий HTML: используйте partials и layout.
- Не помещайте интерактивную логику в Handlebars.
- Каждый JS-модуль должен безопасно работать, если нужный элемент отсутствует на странице.
- Новые страницы обязательно добавляйте в `webpack/pages.js`.
- Не редактируйте файлы внутри `build/` вручную.
- Не храните секреты и токены в шаблонах или JavaScript.
- Для внешних ссылок с `target="_blank"` используйте `rel="noopener noreferrer"`.
- Проверяйте мобильный вид после изменения SCSS.
- После изменения структуры запускайте production-сборку.

## Проверка перед передачей

Выполните:

```bash
npm run build:dev
npm run build:prod
```

Затем проверьте:

- открывается ли `build/prod/index.html`;
- работает ли переход на страницу about;
- переключается ли светлая и тёмная тема;
- работает ли ссылка вишлиста;
- нет ли горизонтального скролла на мобильной ширине;
- присутствуют ли title и description;
- нет ли ошибок в консоли браузера.

## Частые проблемы

### Не найден модуль

Проверьте:

- правильность имени файла;
- путь в `webpack/pages.js`;
- наличие расширения `.js` или `.scss`;
- выполнен ли `npm install`.

### Не отображается partial

Проверьте регистрацию partial в `webpack/webpack.common.js` и имя вызова:

```hbs
{{> partial-name}}
```

### Старые файлы попали в сборку

Удалите каталог `build/dev` или `build/prod` и повторите сборку. В production-конфигурации очистка выполняется автоматически.

### Dev Server не запускается

Проверьте, что порт 3000 свободен, затем повторите:

```bash
npm run start
```

## Линтинг

В проекте предусмотрена команда:

```bash
npm run lint
```

Конфигурация `eslint.config.js` добавлена: проверяются неопределённые/неиспользуемые переменные, недостижимый код, постоянные условия и строгие сравнения. Линтер не заменяет браузерную проверку.

## FRONT-001: работа с концептом

Главная страница включает hero с преимуществами, интерактивное превью и тарифы.
Контент — `src/data/index.js`, композиция — `pages/index.hbs`.
Новые модули `navigation`, `app-preview`, `wishlist` подключены в `webpack/pages.js`.
SVG-логотип и горы находятся в partials; PNG из `concept/` служат только эталонами.

После изменения Handlebars, данных, добавления partials или изменения манифеста
перезапустите `npm run start`: HTML сейчас вычисляется при загрузке конфигурации.
SCSS и JS обновляются стандартным watcher Webpack.

Полная таблица сопоставления — [landing-components.md](landing-components.md).
Результаты проверок и ограничения — [tasks/001-validation.md](tasks/001-validation.md).

### Вишлист и темы

`wishlist.telegramUrl` пуст до получения согласованного адреса.
CTA открывает модальное окно; отключённая кнопка Telegram не считается рабочей интеграцией.
После согласования заполните адрес и замените пояснение о недоступности.
Поле `canonical` также заполняется только после утверждения домена.

Цены взяты из концепта с пометкой illustrative; не удаляйте предупреждение без согласования.
Connect в телефоне переключает только локальное демонстрационное состояние.
EN — единственный доступный язык, переводы не добавлены.

Тема хранится в `localStorage['nordel-theme']`. Для проверки системного выбора
удалите ключ; затем измените системную цветовую схему. Проверьте сохранение после перезагрузки.
Проверьте закрытие окна вишлиста Escape и возврат фокуса.

### Проверки

```bash
npm run build:dev
npm run build:prod
npm run lint
```

Проверяйте сборку через HTTP, а не только открытием файла:
375, 768 и 1440 px в light/dark, Chrome, Firefox и WebKit.
WebKit-автоматизация не заменяет проверку в настоящем Safari на целевом устройстве.
Для совпадения с PNG сравнивайте соответствующую секцию при ширине 1440 px,
одинаковых координатах header и секции, без масштабирования.
Фиксируйте расхождения, ошибки консоли/ресурсов, горизонтальный скролл и клавиатурное управление.

### Поддержка общего footer

`src/templates/partials/footer.hbs` подключён в общем layout на главной и About. Логотип переиспользует `logo.hbs`; меню ссылается на секции `./index.html`. Стили и адаптивность находятся в `src/styles/base.scss`, цвета используют общие токены обеих тем. Мобильное меню footer всегда открыто.

Кнопка footer использует `data-wishlist-open`. Для каждой новой страницы с общим layout подключайте модуль `wishlist` в `webpack/pages.js` и передавайте данные `wishlist`, как в `src/data/about.js`. Окно вишлиста уже включено в layout, повторно добавлять его в шаблон страницы не нужно.

Privacy Policy и Terms of Use пока используют согласованные `href="#"`; заменяйте их только на предоставленные адреса. После изменения footer проверяйте index и about на 375/768/1440 px в обеих темах, включая переходы меню, открытие окна с кнопки footer, Escape, возврат фокуса и отсутствие горизонтального скролла. Сохраняйте результаты отдельно от сравнений секций с PNG: footer отсутствует в концептах.
