# Роль: DevOps / релизы

- **Цель:** развёртывание и публикация всех компонентов.
- **Зона:** хостинг, домен, HTTPS, размещение через офшорные IP, CI/CD, мониторинг, резервные копии, публикация в магазинах.
- **Входы:** доступы к хостингу (пока не переданы), сборки от разработчиков.
- **Выходы:** работающие окружения, инструкции без секретов.
- **Границы:** конкретные адреса инфраструктуры и доступы хранятся вне репозитория. Ссылки на публичный сайт и GitHub приведены ниже.
- **Готовность:** компонент доступен после деплоя и может быть откачен назад.

### Публикация и проверка

1. В настройках репозитория **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
2. Изменения в `main` запускают сборку и деплой автоматически. Для ручного запуска открыть **Actions → Build and deploy website → Run workflow** и выбрать `main`.
3. В [GitHub Actions](https://github.com/nordelVPN/company_nordel-landing_Native/actions) проверить успешное завершение заданий `build` и `deploy`.
4. Открыть адрес из окружения `github-pages`. Адрес проекта: [лендинг Nordel](https://nordelvpn.github.io/company_nordel-landing_Native/).
5. Проверить главную страницу, `about.html`, загрузку CSS, JavaScript и изображений, навигацию и переход в Telegram.

Pull request выполняет сборку и проверку HTML без публикации. Ошибка сборки блокирует задание deploy. Пользовательские секреты для текущего workflow не требуются: используются разрешения GitHub Actions.

### Откат

Для возврата к предыдущей версии создать revert-коммит проблемного изменения в `main` через обычный процесс проверки изменений. Push запустит повторную сборку и публикацию. После деплоя проверить сайт по инструкции выше. Процедура отката пока не испытана.
